# Generation Algorithm

## Input

- source math corpus
- Cycle seed equation/family
- Cycle Build Spec
- Cycle Amendment file

## Algorithm

1. Normalize source definitions.
2. Instantiate byte state space.
3. Quotient/organize states by allowed orientation equivalences.
4. Select/derive 120 deterministic Field Generator identities.
5. Evaluate Generator pair compatibility.
6. Build typed compatibility graph.
7. Search for required base manifold counts by size/color.
8. Verify every base manifold closure.
9. Enumerate all base manifold unordered pairs.
10. Evaluate fusion.
11. Evaluate emergent coupling.
12. Store VALID / TERMINATES / NOT_APPLICABLE explicitly.
13. Materialize all valid derived QMOs.
14. Generate RenderSpec for each renderable QMO.
15. Run validation.
16. Emit immutable Cycle lock.

## Selection principles for 120 Generators

The Generator catalog should not be chosen to maximize raw connectivity.

Prefer:
- useful overlap,
- fallback low-order closures,
- higher-order target paths,
- nontrivial termination space,
- no universally mandatory Generator,
- no isolated dead Generator unless deliberately designed,
- multiple strategic routes,
- hidden pairings that are mathematically earned.

## Base manifold selection

The base catalog is a curated basis inside the larger closure landscape.

It is not necessarily exhaustive.

Base manifolds should:
- cover all Cycle colors,
- share Generators strategically,
- preserve deck-building optionality,
- avoid trivial complete connectivity,
- provide meaningful tempo and long-game paths.
